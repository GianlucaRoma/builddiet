Know what can come back.

BuildDiet checks which files in your projects can be recovered before suggesting what to remove. It measures the space you gain and the time it would take to restore those files.

The workflow

A deletion plan backed by a recovery test.

Built for projects where generated outputs, copies and irreplaceable inputs sit side by side.

01 / Analyze

Find candidates

Inspect projects inside a folder and identify large files or directories worth checking.

02 / Prove

Test recovery

Check an identical copy, archive, Git source or rebuild command. Keep anything whose original bytes cannot be recovered.

03 / Choose

Review the trade-off

See space saved and measured rebuild time. Reclaim manually, then restore a project if you need its files again.

Use it with eyes open

A project tool, not a whole-disk cleaner.

Beta guidance

Start with analysis and manual reclaim on a backed-up project. BuildDiet does not inventory or safely clean every kind of file on a disk. Rebuild scripts run as real programs during testing and can affect services outside the test copy; review them before approval. Multi-gigabyte workspaces and trees with very many small files are not yet validated.

Get started

Try analysis first.

Clone the repository, install it in a virtual environment, then point BuildDiet at a project folder. Read the proposed options before reclaiming anything.

Setup and documentation ↗
$ git clone https://github.com/GianlucaRoma/builddiet.git
$ cd builddiet
$ python3 -m venv .venv
$ .venv/bin/python -m pip install .
$ .venv/bin/builddiet analyze ~/Projects/app
