# BD-PRIOR: prior-art audit

**Question.** Does existing work already combine the following?

> **black-box remove → regenerate → verify → measure rebuild cost → minimum-cost reclaim plan**
> applied to files and directories the tool did not create and has no lineage for.

**Result.** We found no work that combines all of these. Every individual element has prior art, and the combination of *measured rebuild cost* with *choosing what to delete to reach a space target* is old (2010 and earlier). **BuildDiet must not be described as new, first or unique.** The accurate claim is narrow; see the recommended wording at the end.

The audit was done on 2026-09-23. It is not a legal freedom-to-operate opinion.

## The five elements

| | Element | What BuildDiet does |
|---|---|---|
| **A** | Regenerability established by *experiment* on unmanaged data | Removes the data in a sandbox copy and runs the user's workflow. No lineage, catalog or declaration is needed. |
| **B** | Verification gate and identity check | The verify command must pass, and the files must come back (SHA-256). |
| **C** | Rebuild cost measured by the same experiment | Time of the run without the item, minus the warm baseline. |
| **D** | Minimum-cost reclaim plan for a byte target | Min-cost covering knapsack solved exactly with dynamic programming. |
| **E** | Stale or corrupt copy detection | A second regeneration separates "the original differs" from nondeterministic output. |

## Findings per element

* **C + D (cost-aware reclaim to a target):** clearly prior art. Nectar (2010) already deletes derived data by a cost/benefit ratio until a space threshold is reached. Hitachi US11842308B2 deletes toward a capacity-reduction target using regeneration cost. Yuan et al. compute minimum-cost storage strategies. kache is converging on the same objective for build caches. BuildDiet's exact knapsack is an ordinary technique.
* **B (rebuild and verify identity):** prior art in reproducible-builds tooling and in the CI pattern that regenerates generated files and diffs them.
* **E (stale detection by regenerating):** the CI regenerate-and-diff pattern detects the same drift for *declared* generated files. Building twice to detect nondeterminism is also established practice in reproducible builds.
* **A (experimental regenerability of unmanaged data):** **not found.** In every cost-aware system above, regenerability is *known* ahead of time: from the system's own lineage (Nectar, Chimera, Tachyon, Hitachi, Yuan), from declarations (Snakemake, Nix, "regeneratable" metadata), or from catalogs and `.gitignore` (cleaners). The black-box removal experiments we found have different goals: *necessity* (debloating, ablation) or *reproducibility* (rebuilderd). They do not establish regenerability in order to delete data.
* **A + B + C + D together:** **not found.**

## Search scope and limits

* **Papers:** web search that surfaced USENIX (OSDI, USITS), ACM (SIGMOD, ISSTA, FSE), VLDB, ScienceDirect, arXiv, IEEE and Semantic Scholar pages. We did not run a direct Google Scholar or ACM full-text query, and we did not follow citation chains beyond the items listed.
* **Patents:** Google Patents pages found through targeted queries. Full claims were read for US9594796B2, US11842308B2, US8375192B2 and US7685174B2. We did **not** do a classification (CPC) search. Non-US and non-English filings are not covered.
* **GitHub:** web search plus the public GitHub search API for repositories and issues. The API was unauthenticated, so it was rate-limited, and we could not use code search.
* Queries targeted the specific combination (regenerate or rebuild cost, eviction, lineage, derived data, black-box removal). As requested, we did not search generic "disk cleaner" terms.

Absence of evidence from a search of this size is **not** proof of novelty.

## Recommended wording

Use:

> BuildDiet establishes by experiment, not by declaration or catalog, which parts of an existing workspace your own workflow can regenerate. It measures what each costs to rebuild and plans the cheapest proven way to reclaim space. Cost-aware reclamation of derived data is well established (e.g. Nectar, OSDI 2010). We are not aware of prior work that establishes regenerability of unmanaged data by removal experiments and feeds the measured costs into such a plan. See docs/BD-PRIOR.md.

Do not use: "new", "first", "unique", "novel", or "nobody has done this".
